## 4. Defects (BUGS.md format, IMPL §7.1)

### QA-T2.6-01: Service "activate" inside an inactive family reports success but has no effect
- Severity: **Medium**. Owner: A03. Requirement: CFG-RULE-001, OPS-ADMIN-023, CAT-SVC-002 (BP §64 "Services can be active in one city but inactive in another"; BP §29 the server is the source of truth; CLAUDE.md "Never show success before the server confirms").
- Where: `services/api/src/modules/catalog/catalog.service.ts:156-166` (`setServiceActive`) and `:73-79` / `:100-103` (`availability` checks `familyActive` before any service-level row). The contract has the same gap: `contracts/catalog.yaml` `setServiceActive` returns 200 `Activation` and has no refusal code for this case.
- Repro: on a seeded DB, call `setServiceActive({cityId: lahore, serviceId: pest_control.ant_treatment, isActive: true, …})`. It returns `{isActive: true}` and writes an audit row `SERVICE_SET_ACTIVE`, but `availability()` then returns `{available:false, reason:'FAMILY_INACTIVE'}`. The test `tests/e2e/api/t2.6-catalog-config.qa.db-spec.ts` › "[CFG-RULE-001] a service "activate" that is reported saved must make the service available (BP §64)" fails with `saved={"…","isActive":true} availability={"available":false,"reason":"FAMILY_INACTIVE"}`.
- Expected: either the server refuses (for example 409/422 `FAMILY_INACTIVE`, declared in the contract) or the service-level `true` row makes the service available. Which rule applies is an interpretation, so A00 may want an OQ. Silent success is wrong either way: an A23 operator would believe the service is live in Lahore.

### QA-T2.6-02: Platform reader change breaks `missingFailClosedKeys` (integration, A01 ↔ A03)
- Severity: **High for the gate**, not a T2.6 defect at handoff time (per the A00 note). Owners: A01 (reader) and A03 (caller). Requirement: SEC-AUTH-004, SEC-BASE-006, MEDIA-004 (SEC-REVIEW-T1.1-1.3 #1).
- Where: `packages/platform/src/config/config-service.ts:254` (modified at 08:15 during this review). `CachedConfigService.get` now **throws** `ConfigNotSetError` for fail-closed keys instead of returning `not_configured`. `services/api/src/modules/config/config-readiness.ts:27` calls `config.get(...)` and expects a result.
- Repro: `pnpm --filter @kaamkaro/api exec vitest run src/modules/config` fails on `[SEC-AUTH-004] every OTP/login/media limit reported missing while null; deployed envs fail closed` with `ConfigNotSetError: Config "auth.otp.expiry_seconds" is not configured (VALUE_NULL)`. The seed DB test `[CFG-RULE-003] owner values are read through the store and A01 reader` fails on `auth.otp.max_attempts` for the same reason. Both passed (84/84, 9/9) before the edit.
- Fix direction: `missingFailClosedKeys` should use `inspect` (or catch `ConfigNotSetError`), or A01 keeps `get` non-throwing. The two fail-closed lists must also agree: A01 has `FAIL_CLOSED_KEY_PREFIXES` and A03 has `FAIL_CLOSED_KEYS`.

### Low / observations (not blocking)
- **L-1** (A03, CFG-RULE-001): `contracts/config.yaml` lists 8 error codes. `ConfigWriteError` also has `ACTOR_REQUIRED` 401 (`config-admin.service.ts:37`), which the contract does not declare. Error responses in both contracts have only a description and no `ErrorEnvelope` `$ref` from `common.yaml`. `setServiceActive` declares no 404. `setCityActive` returns 204 while the family and service PUTs return 200.
- **L-2** (A03, I18N-006 / RQ-010): the seed never updates existing names (DO NOTHING). Urdu corrections from the A14 review will not reach seeded databases by re-running the seed; they need a data migration or an admin edit path.
- **L-3** (A03/A01, IMPL §3.4): "DRAFT" is only a YAML comment. A machine-readable marker (for example `x-status: draft`) would let the structure spec or traceability tool block consumers from coding against a draft.
- **L-4** (A01, IMPL §7.4): `GUARDED_PATH` in `infra/ci/lib/hardcoded-values.ts:13` does not cover `modules/config` or `modules/catalog`. No violation exists today (manual scan).
- **Scope note:** the IMPL §6 T2.6 task text asks for "other Pakistani cities `is_listed = true, is_active = false`". None are seeded, because BP names none. This is correctly raised as OQ-084 (golden rule 1) and is not part of the acceptance line.
