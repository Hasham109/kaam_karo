### Observations for A00 (no defect in T2.3)

- **F-04, citation wording.** 77 of 715 comments cite only a D-xxx or a requirement ID, with no literal "BP §", e.g. `booking.crew_size` (D-004, D-018) and `media_object.storage_key` (D-001, INFRA-003). CLAUDE.md rule 1 accepts "BP §n or D-xxx", and every requirement ID traces to a BP §/D-xxx in REQUIREMENTS.md, so I accept this. If A00 reads IMPL §6 literally as "BP §" only, these 77 docs need a BP § added.
- **F-05, ledger correction direction (A09 + A00).** The partial unique indexes allow one `COMMISSION_DEBIT` and one `JOB_CREDIT` per booking, and there is no free-standing debit. After a full reversal, a corrected debit cannot be re-posted. An under-charged commission can therefore never be corrected **upward**. Likewise, a wrong CASH/DIGITAL `payment_method_record` cannot be corrected, because it is unique and append-only. This matches `docs/screens/admin.md:534` (reversal only), but the business case is not decided. Suggest a new OQ.
- **F-07.** ARCH §6.7 names Warning 1 and Warning 2 as states. The schema uses `WARNING` + `rating_warning_count`. This is equivalent; A05 should confirm it in T5.x.
- `SPECIALIZED_VERIFIED` is a value of `verification_level`, and BP §22.1 marks that level "later". The enum value is harmless; no flow may set it at launch.
- `formatPkr` (T0.6) takes whole rupees as a `number`, while the schema stores BigInt paisa. T1.4 needs a minor-units formatter (see T0.6-qa.md).
