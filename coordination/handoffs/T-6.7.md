## 1. Summary of Completed Work

1. **Unpaid-Commission Hard Filter in Matching Engine:**
   - Evaluated in matching engine hard filters (`HardRuleCode.UNPAID_COMMISSION`).
   - Dynamically checks `isProviderHiringBlocked`: checks provider balance against configurable threshold `ledger.max_negative_balance` (defaults to 0 paisas).
   - If balance < 0 (liability owed ≥ threshold), the provider is excluded from search results and match candidate lists.

2. **Transition & Quote Guards (D-020, D-021, LEDGER-NEG-001..005):**
   - **Accept Booking Guard:** Added `acceptBookingGuard` blocking `REQUESTED → ACCEPTED` and `QUOTE_PENDING → QUOTED` with `409 UNPAID_COMMISSION` if provider balance < 0.
   - **Send Quote Guard:** Blocks provider quote submission in `QuotesService.createQuote` if balance < 0 (`409 UNPAID_COMMISSION`).
   - **Favorite Rebook Guard:** Blocks booking creation with preset provider (`createBooking` in `BookingService`) with `409 UNPAID_COMMISSION`.
   - **D-021 Job Execution Block:** Transition table guards block starting already-accepted jobs while balance is negative:
     - `SCHEDULED → PROVIDER_EN_ROUTE` refused with `409 UNPAID_COMMISSION`.
     - `ARRIVED → IN_PROGRESS` refused with `409 UNPAID_COMMISSION`.

3. **"Pay Company" Flow in Partner App (P15; ARCH §6.8, D-020, LEDGER-PAY-001..004):**
   - Partner screen `P15EarningsWalletScreen.tsx` (P15) displays:
     - Current account balance with negative balance warnings.
     - Unpaid commission block warning banner showing exact amount owed.
     - Kaam Karo bank/wallet account details for manual deposit.
     - "Pay company" submission form: amount in rupees, bank/wallet transaction reference ID, optional payment receipt image attachment.
     - Submission history list showing `SUBMITTED`, `APPROVED`, or `REJECTED` status.
     - Full ledger transaction history with positive/negative impacts.
   - **Invariant (D-020, LEDGER-PAY-003):** Submitting a payment reference creates a `CommissionPaymentSubmission` record in `SUBMITTED` status and does **not** unblock hiring.

4. **Finance Verification Queue in Admin (A09; ARCH §6.8, D-020, D-021, LEDGER-PAY-005..007):**
   - Admin screen `A09PaymentsScreen.tsx` (A09) accessible exclusively to `FINANCE` and `SUPER_ADMIN` roles:
     - Lists all pending `CommissionPaymentSubmission` items.
     - Decision modal requiring mandatory audit reason (`ROLE-003`).
     - **Approval (`APPROVE`):** Atomically creates an audited `COMPANY_PAYMENT_CREDIT` ledger row and links `commissionPaymentSubmissionId`. Auto-unblocks provider if resulting balance ≥ 0.
     - **Rejection (`REJECT`):** Marks submission `REJECTED` with audit reason.
   - **Separation of Duty (ABUSE-010, OQ-083):** Staff/provider user is strictly forbidden from approving or rejecting their own payment submission (`CANNOT_DECIDE_OWN_SUBMISSION`).

5. **Dynamic Platform Configuration:**
   - Dynamic configuration key `ledger.max_negative_balance` (defaults to 0 paisas) read from `PlatformConfigService` with fallback to 0.

6. **Domain Events (ARCH §7):**
   - `provider.balance_negative`: emitted when settlement causes balance to drop below threshold.
   - `provider.commission_payment_submitted`: emitted on submission.
   - `provider.commission_payment_rejected`: emitted on rejection.
   - `provider.balance_cleared`: emitted when approval restores balance to ≥ 0.

7. **OpenAPI 3.1.0 Contract:**
   - `contracts/payments.yaml` documents endpoints:
     - `POST /v1/payments/company/submit` (`LEDGER-PAY-001`)
     - `GET /v1/payments/company/submissions/provider/{providerProfileId}` (`LEDGER-PAY-002`)
     - `GET /v1/payments/company/submissions/pending` (`LEDGER-PAY-005`)
     - `POST /v1/payments/company/submissions/{submissionId}/decision` (`LEDGER-PAY-006`)
     - `GET /v1/payments/provider/{providerProfileId}/unpaid-block` (`LEDGER-NEG-001`)
