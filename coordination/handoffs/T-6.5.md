## 1. Summary of Completed Work

2. **Safepay Gateway Adapter (`SafepayPaymentGateway`):**
   - Implemented `SafepayPaymentGateway` conforming to the `PaymentGateway` interface in `services/api/src/modules/payments/safepay-payment-gateway.ts`.
   - **Order Initiation (`initiate`):**
     - Calls Safepay API (`/order/v1/init`) with merchant key, client key, amount (PKR converted from paisa minor units), currency, environment, and metadata (`paymentRef`, `bookingId`, `customerProfileId`).
     - Returns tracker token (`gatewayRef`) and hosted checkout URL (`checkoutUrl`) formatted with beacon token: `${checkoutBaseUrl}?beacon=${token}&source=custom`.
     - Supports resilient error handling and throws `BadGatewayException` on non-200 or network communication failures.
   - **Tracker Querying (`query`):**
     - Queries Safepay tracker status (`/order/v1/{token}`) for reconciliation (`PAY-005`).
     - Maps Safepay statuses (`PAID`, `COMPLETED`, `SETTLED` → `PaymentStatus.SUCCEEDED`; `FAILED`, `CANCELLED`, `EXPIRED` → `PaymentStatus.FAILED`; other → `PaymentStatus.PENDING`).
     - Returns `{ found: false }` on HTTP 404 for reconciliation exception reporting.
   - **Refunds (`refund`):**
     - Dispatches refund requests to `/order/v1/{token}/refund`.
     - Maps response to `RefundStatus` (`SUCCEEDED` / `FAILED` / `ISSUED`).
   - **Zero Raw Card Data Invariant (`PAY-008`, `SEC-BASE-009`):**
     - Zero card number (PAN), CVV, or expiry inputs enter the Kaam Karo platform. All sensitive card entries occur strictly on Safepay's PCI-DSS Level 1 compliant hosted checkout page.

3. **Cryptographic HMAC-SHA256 Webhook Verification:**
   - Implemented `verifyWebhookSignature` in `SafepayPaymentGateway`:
     - Computes HMAC-SHA256 digest over the raw payload using the Safepay webhook secret.
     - Compares signatures using timing-safe buffer comparison (`crypto.timingSafeEqual`) to prevent timing attacks.
   - Implemented `createWebhookSignature` for sandbox certification and testing.

4. **Webhook Controller & Service Ingress:**
   - Added `@Public() @Post('webhook/safepay')` in `PaymentsController`:
     - Reads `x-sfpy-signature` header and raw payload.
     - Enforces HMAC-SHA256 verification via `PaymentsService.handleSafepayWebhook`.
     - Rejects unauthorized or tampered webhooks with `401 Unauthorized` (`INVALID_WEBHOOK_SIGNATURE`).
     - Resolves internal `paymentRef` via payload metadata or tracker token (`gatewayRef`).
     - Idempotently executes digital payment state transition (`SUCCEEDED` / `FAILED`) and triggers ledger settlement (`recordJobSettlement`).

5. **Dynamic Gateway Provider Factory:**
   - Configured `PAYMENT_GATEWAY` provider in `PaymentsModule` with factory injection:
     - Defaults to `FakePaymentGateway` for fast, zero-credential local tests and offline dev.
     - Injects `SafepayPaymentGateway` when `PAYMENT_GATEWAY_PROVIDER === 'safepay'`.
     - `PaymentsService` also injects `SafepayPaymentGateway` to ensure Safepay webhook ingress is always verified.

6. **OpenAPI 3.1.0 Contract:**
   - Updated `contracts/payments.yaml` with the `/v1/payments/webhook/safepay` endpoint, signature header documentation, and requirement IDs (`PAY-001`, `PAY-008`, `EXT-001`, `SEC-BASE-009`).
   - Verified with contract test suite (`pnpm --filter @kaamkaro/contracts test`: 43/43 tests pass).
