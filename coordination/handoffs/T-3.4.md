## What I Built

### 1. OpenAPI 3.1.0 Contract (`contracts/booking.yaml`)
- Published contract for Booking Service under OpenAPI 3.1.0 (semver 0.1.0).
- Registered in `contracts/README.md`.
- Endpoints defined:
  - `POST /v1/bookings`: Creates a new booking. Refuses client-sent `status` (`BOOK-STATUS-016`, `SEC-BASE-007`). Returns server-computed status (`DRAFT`, `REQUESTED`, or `QUOTE_PENDING`) and `allowedNextActions`.
  - `GET /v1/bookings/{id}`: Retrieves booking details and role-tailored `allowedNextActions`.
  - `POST /v1/bookings/{id}/transitions`: Requests a status change through the canonical state machine (`BOOK-STATUS-001..017`).
  - `POST /v1/bookings/{id}/cancel`: Cancels booking with reason code and cancellation policy evaluation (`BOOK-CANCEL-001..003`).
  - `POST /v1/bookings/{id}/no-show`: Records a customer or provider no-show with mandatory party attribute (`BOOK-CANCEL-004..005`, `BOOK-STATUS-017`).
  - `POST /v1/bookings/{id}/safety-stop`: Emergency / unsafe situation stop (`BOOK-CANCEL-006`).
  - `GET /v1/bookings/{id}/events`: Lists immutable audit Job Events in chronological order (`DATA-002`, `DATA-004`).
- Validated by `@kaamkaro/contracts` schema tests (35/35 tests pass).

### 2. Canonical Transition Table & Oracle (`transition-table.ts`, `booking-transitions.oracle.ts`)
- Implements the exact ARCH §6.1 / BP §15 state machine:
  - 17 Booking Statuses (`DRAFT`, `REQUESTED`, `QUOTE_PENDING`, `QUOTED`, `ACCEPTED`, `SCHEDULED`, `PROVIDER_EN_ROUTE`, `ARRIVED`, `IN_PROGRESS`, `AWAITING_APPROVAL`, `COMPLETED`, `DISPUTED`, `CANCELLED`, `EXPIRED`, `CLOSED`, `REJECTED`, `NO_SHOW`).
  - 38 valid transitions with designated actor roles (`CUSTOMER`, `PROVIDER`, `ADMIN`, `SYSTEM`), Urdu/English labels, and business guards.
  - Exactly 0 transitions out of `CLOSED` (`BOOK-STATUS-015`).
  - Terminal statuses (`CANCELLED`, `EXPIRED`, `REJECTED`, `NO_SHOW`) only transition to `CLOSED`.
  - Transition guards:
    - `crewSizeGuard`: Requires `crew_size >= 1` upon provider acceptance if not already set (D-004, `PROV-CREW-002`).
    - `unpaidCommissionGuard`: Rejects `START_TRIP` and `START_WORK` with `UNPAID_COMMISSION` if provider negative balance limit is exceeded (`LEDGER-NEG-005`, `D-021`).
    - `noShowGuard`: Enforces mandatory `noShowParty` (`BOOK-STATUS-017`).
- Independent oracle fixture `booking-transitions.oracle.ts` for bidirectional test verification (`test-strategy.md` §4.1).

### 3. CI Hook Guard (`services/api/src/modules/booking/tools/check-transition-table.ts`)
- Fulfills the `transition-table` CI guard requirement in `infra/ci/lib/hooks.ts`.
- Reads the canonical source file and verifies all 289 status pairs (17 x 17): asserts exactly 38 allowed, 251 rejected, zero out of `CLOSED`, and terminal status constraints.
- Integrated into `pnpm run guards`.

### 4. Booking Service Engine (`booking.service.ts`)
- Enforces server-only status determination (`BOOK-STATUS-016`, `SEC-BASE-007`).
- Quote-required services route to `QUOTE_PENDING` on submit (`CAT-SVC-003`, `D-028`); others route to `REQUESTED`.
- Atomic state transitions inside Prisma `$transaction`:
  - Optimistic locking via `version` increment.
  - Writes immutable `JobEvent` row with actor, action, previous status, new status, reason, and source metadata (`DATA-002`, `DATA-004`).
  - Returns updated booking with new `allowedNextActions`.
- Safety emergency stop: `ARRIVED -> CANCELLED`, `IN_PROGRESS/AWAITING_APPROVAL -> DISPUTED` with safety case audit tagging (`BOOK-CANCEL-006`).

### 5. Controller & NestJS Module Integration (`booking.controller.ts`, `booking.module.ts`, `app.module.ts`)
- Registered `BookingModule` in NestJS `AppModule.forRoot()`.
- Exposes REST endpoints with `AuthGuard` and role resolution.
