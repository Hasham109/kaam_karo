- `seed-sql.ts` + `run.ts`:
  - Builds one transaction and applies it through `prisma db execute --stdin` (migration owner).
  - **Idempotent:** ON CONFLICT / NOT EXISTS, so admin changes are never overwritten. config_rule gets a seed row only when the key has no GLOBAL row (append-only).
  - `node prisma/seed/run.ts --print` shows the SQL.

**Activation model** (catalog_activation, CFG-RULE-001):
- Lahore has one row per family: 10 active (D-024) and 12 inactive.
- No service-level rows are seeded; a service follows its family.
- Offered = city listed + active, active zone, family active, no service row switching it off, and a non-empty selling-mode set (CAT-SVC-002).

**Config module** (`services/api/src/modules/config`):
- `config-keys.ts` is the registry of all 71 keys. Per key: kind, allowed scopes, requirement IDs, sources, `decidedBy` (read-only, OQ-078 default), `failClosed`, `approval: TWO_PERSON` (OQ-076) and `whileNull` (the safe behaviour). It holds no values.
- `PrismaConfigRuleStore` implements A01's `ConfigRuleSource` (RQ-006) and `append(version, audit)`: insert + audit in one transaction.
- `ConfigAdminService.setRule` checks, in order: known key, actor, reason, decided key → 403, two-person key → 409, scope allowed, scope ID exists (catalog), value kind, **no back-dating** (`effective_from` ≥ now). It then appends the new version + audit and calls `invalidate(key)`. `history(key)` returns versions newest first.
- `missingFailClosedKeys(config)` + `mustFailClosed(appEnv)` support the start-up / action guard (SEC-REVIEW-T1.1-1.3 #1).
- `ConfigRulesModule` (global) provides `CONFIG_SERVICE` (A01 `CachedConfigService`), `CONFIG_RULE_SOURCE` and `ConfigAdminService`, on top of the global PlatformModule.

**Catalog module** (`services/api/src/modules/catalog`):
- `PrismaCatalogRepository` and `CatalogService`:
  - `listedCities`, `availability(cityId, serviceId)` (with reason), `activeCatalog(cityId)`;
  - `setCityActive` (only listed cities), `setFamilyActive`, `setServiceActive` (refused with an empty selling-mode set). All three need an actor and a reason, and are audited in the same transaction.
  - `exists(scope, id)` is the ScopeRefCheck for config.
- **No create-family/create-service method exists** (SCOPE-CAT-001; tested).
- `PlatformAuditPort` maps entries onto A01's `AuditWriter` (actor role ADMIN; the masker applies).

## How to use it (for consumer agents)
- **Read config** (any module): `@Inject(CONFIG_SERVICE) config: ConfigService`, then:
  - `config.get('availability.max_service_radius_m', configParsers.integer, { cityId })`. When the result is not `configured`, apply the key's `whileNull` behaviour.
  - Or `config.require('commission.rate', configParsers.ratio)`, which fails closed.
  - Never hard-code the value.
- **Catalog** (A04/A05/A07/A11 via future endpoints): inject `CatalogService` from `modules/catalog`.
  - `availability(cityId, serviceId)` before accepting a request: a not-available result returns the reason (`CITY_NOT_ACTIVE` = "not active yet", SCOPE-GEO-001).
  - `activeCatalog(cityId)` for C06/C09.
- **Admin** (A13, T5.2):
  - `CatalogService.setFamilyActive/setServiceActive/setCityActive({ cityId, …, isActive, actorUserId, actorSubRoles, reason })`.
  - `ConfigAdminService.setRule({ key, scope, scopeRefId, value, effectiveFrom?, actorUserId, actorSubRoles, reason })`, which throws `ConfigWriteError` (`code`, `httpStatus`). `CONFIG_KEYS` drives the editor (kind, read-only, whileNull).
- **Start-up / OTP / upload guard** (A01/A02/A08): in staging/production, refuse while `missingFailClosedKeys(config)` is non-empty (`LIMIT_NOT_CONFIGURED`).
- **Seeding** a DB: `node prisma/seed/run.ts` from services/api, after `prisma migrate deploy`.
