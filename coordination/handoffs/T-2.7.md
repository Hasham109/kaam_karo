## What I Built

### 1. BUG-0005 Fix: DB Role Guard (`packages/platform/src/db-role-guard.ts`)
- Fixed critical security vulnerability where the startup DB role guard checked `rolsuper` and `rolbypassrls` but omitted checking `rolcreaterole` and `rolcreatedb`.
- Updated role query in `fetchDbRole()`:
  ```sql
  SELECT r.rolname AS login,
         r.rolsuper AS is_superuser,
         r.rolbypassrls AS bypasses_rls,
         r.rolcreaterole AS can_create_role,
         r.rolcreatedb AS can_create_db,
         ...
  ```
- Added checks in `dbRoleProblems()`:
  - Rejects roles where `can_create_role === true` (`login "..." has CREATEROLE`).
  - Rejects roles where `can_create_db === true` (`login "..." has CREATEDB`).
- Unit tests in `packages/platform/src/db-role-guard.spec.ts` updated to verify rejection of both privileges. All 249 platform tests pass.
- Marked `BUG-0005` as `FIXED` in `coordination/BUGS.md`.

### 2. Backup CLI Tool (`infra/scripts/db-backup.ts`)
- Script: `pnpm run db:backup [target_db]`.
- Implements consistent PostgreSQL logical dumps using `pg_dump` with `--clean --if-exists --no-owner --no-acl`.
- Computes SHA-256 checksum buffer and writes companion `.sha256` checksum file for tamper-evidence.
- Automatically handles both containerized PostgreSQL (`docker exec`) and native CLI environments.
- Memory safe: buffers large SQL streams and writes directly to disk under `backups/`.
- Git ignores `backups/` dumps to prevent accidental commit of database state.

### 3. Restore CLI Tool (`infra/scripts/db-restore.ts`)
- Script: `pnpm run db:restore <backup_file> <target_db>`.
- Cryptographic checksum validation: compares file SHA-256 against expected hash in `.sha256` file before executing restore; aborts immediately on tampering or corruption.
- Cross-platform piped input stream: feeds SQL dump buffer directly into stdin of `psql`, avoiding shell redirection vulnerabilities or path escaping bugs on Windows/Linux.

### 4. Automated Disaster Recovery Drill (`infra/scripts/restore-drill.ts`)
- Script: `pnpm run db:restore-drill`.
- Simulates complete end-to-end backup and restoration cycle:
  1. Bootstraps clean source database (`kaamkaro_t27_source`).
  2. Applies full migrations (`pnpm db:deploy`) and seed data (`pnpm db:seed`: 22 families, 351 services, 1 city, 72 config keys).
  3. Dumps logical backup with SHA-256 checksum generation.
  4. Prepares isolated drill target database (`kaamkaro_restore_drill`).
  5. Restores dump with cryptographic validation.
  6. Executes deep verification checks:
     - PostGIS extension point calculation (`POINT(74.34 31.52)`).
     - Base table count (≥ 50 tables across all modules).
     - Catalog rows (Lahore city + 351 active/inactive services).
     - Immutability trigger `kk_location_snapshot_freeze` (attempted update throws SQLSTATE 55000).
  7. Cleans up temporary test databases.
  8. Appends audit record with UTC timestamp, duration, and verdict into `docs/ops/restore-drill-log.md`.
