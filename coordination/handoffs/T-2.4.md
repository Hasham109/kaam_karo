## What I built
**1. OpenAPI Contract** (`contracts/identity.yaml`, v0.1.0):
- Endpoints for customer, partner, and admin authentication:
  - `POST /v1/auth/otp/send`: request 6-digit login OTP for Pakistani mobile numbers (+92 3xx).
  - `POST /v1/auth/otp/verify`: verify OTP with HMAC-SHA256, issue session token, provision user & roles. Supported by `@Idempotent('auth.otp.verify')`.
  - `POST /v1/auth/admin/login`: Step 1 of separate admin auth path (SEC-AUTH-005, ADMIN-ROLE-001), returns challenge ID.
  - `POST /v1/auth/admin/mfa/verify`: Step 2 of admin auth path, verifies TOTP/test code or one-time recovery code, returns session token + active sub-roles.
  - `POST /v1/auth/session/refresh`: extends active session expiry.
  - `POST /v1/auth/session/revoke`: revokes current session.
  - `POST /v1/auth/session/revoke-all`: multi-device sign-out (C27/P21; SEC-AUTH-002).
  - `POST /v1/auth/account/delete-request`: initiates account deletion lifecycle and hold period (SEC-AUTH-008).
- Validated via `@kaamkaro/contracts` test suite (`pnpm --filter @kaamkaro/contracts test`).

**2. OTP & Phone Service** (`services/api/src/modules/identity/otp/`):
- `normalizePakistaniPhone`: normalizes 03xx, 923xx, +923xx into E.164 (+923xxxxxxxxx), strictly rejecting invalid prefixes and malformed numbers.
- `MemoryOtpChallengeStore`: in-memory store for OTP challenges, HMAC-SHA256 hashed with configurable pepper, attempt limiting, lockout enforcement, and send rate limits.
- `FakeOtpSender`: test/dev sender that stores sent OTPs in memory without third-party network egress (Golden rule 3).
- `OtpService`:
  - Rate limiting via `auth.rate_limit.otp_send` (max sends in window).
  - Resend cooldown enforcement via `auth.otp.resend_cooldown_seconds`.
  - Lockout enforcement via `auth.otp.lockout_seconds` and `auth.otp.max_attempts`.
  - Constant-time verification using `crypto.timingSafeEqual` over HMAC-SHA256 digests.
  - Automatic account provisioning for new mobile numbers (`User` + `UserRole` CUSTOMER/PROVIDER).
  - Immediate refusal for `BLOCKED` and `ANONYMISED` accounts (SEC-AUTH-006).

**3. Session Service** (`services/api/src/modules/identity/session/`):
- Generates cryptographically secure session tokens formatted as `kk_sec_<32 hex bytes>`.
- Stores only SHA-256 digest (`tokenHash`) in `device_session` table (SEC-BASE-002); raw tokens are never persisted.
- Configurable TTL: reads `auth.session_ttl` (customer/partner apps) or `auth.admin_idle_timeout` (admin portal) via `ConfigService`.
- Multi-device sign-out (`revokeAllSessions(userId, exceptSessionId)`): revokes all other device sessions in a single query while preserving current session.

**4. Admin Auth & MFA Service** (`services/api/src/modules/identity/admin/`):
- Separate authentication path for staff (SEC-AUTH-005, ADMIN-ROLE-001; BP §27, §34).
- Two-step flow: Step 1 initiates login challenge; Step 2 verifies second factor.
- Supports single-use admin MFA recovery codes (`admin_recovery_code` table): updates `used_at` timestamp so recovery codes can never be reused.
- Sets `mfa_verified_at` on the resulting `device_session`.

**5. Staff Role Lookup & RBAC** (`services/api/src/modules/identity/staff-role-lookup.ts`):
- `DatabaseStaffRoleLookup`: implements `StaffRoleLookup` port (`STAFF_ROLE_LOOKUP`).
- Queries `admin_user` joined with `admin_user_sub_role` where `is_active = true`, `mfa_enrolled_at IS NOT NULL`, and `revoked_at IS NULL`.
- Fulfills **RQ-012**: Replaced `DenyAllStaffRoleLookup` in `CatalogModule` with `DatabaseStaffRoleLookup`.

**6. Account Deletion & Anonymization** (`services/api/src/modules/identity/anonymizer/`):
- `requestDeletion`: sets account status to `DELETION_REQUESTED`, records `deletion_requested_at`, revokes all active device sessions, and sets hold period from `account.deletion_hold_days`.
- `anonymizeUser`: sets `phone_e164`, `display_name`, and `email` to `null`, marks status `ANONYMISED`, records `anonymised_at`.
- Preserves the user UUID so financial and audit integrity is maintained (DATA-003, SEC-AUTH-008).
- Closes **RQ-013 item 1**: Purges the user's records from `idempotency_key` table where `scope = 'user:' || id`.

**7. Guards & Interceptors** (`services/api/src/modules/identity/guards/`):
- `AuthGuard`: extracts Bearer token, verifies hash via `SessionService`, populates `req.user` with userId, surface, and platform roles. Supports `@Public()`.
- `RequireRoleGuard`: enforces platform role checks (`CUSTOMER`, `PROVIDER`, `ADMIN`).
- `RequireAdminSubRoleGuard`: enforces admin sub-role checks (`SUPER_ADMIN`, `OPERATIONS`, `FINANCE`, etc.), verifying that the session has `mfaVerifiedAt`.
- Enhanced `idempotency.interceptor.ts`: resolves unauthenticated phone scope `phone:<phoneE164>` for `/auth/otp/verify` requests.
