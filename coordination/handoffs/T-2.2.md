## How to use it (for consumer agents)
- **Read config** (after A03 wires `CONFIG_SERVICE`, RQ-006): `@Inject(CONFIG_SERVICE) config: ConfigService`.
  - Requirement says "while null, no limit/fee": `const r = await config.get('cancel.window_minutes', configParsers.integer, { cityId }); if (r.status !== 'configured') { /* safe behaviour from the requirement */ }`.
  - Security/money must not proceed without a value: `await config.require('commission.rate', configParsers.ratio)` → throws → client gets 503 `CONFIG_NOT_SET`.
- **Errors**: `throw new AppError('TRANSITION_NOT_ALLOWED', 409, 'Transition not allowed.')` (code UPPER_SNAKE, declared in your contract) or `AppError.of('FORBIDDEN')`. Never return internal messages. Provider-eligibility refusals must use a generic code (RQ-004 item 5).
- **Idempotent endpoint** (create booking, submit request, initiate payment, accept quote, approve charge — REL-008): add `@Idempotent('booking.create')` on the handler. Needs an authenticated `request.user.id` (A02, T2.4; A02 may override `IDEMPOTENCY_SCOPE_RESOLVER`). Still add a business unique constraint where one exists (e.g. one payment per booking) — idempotency is the first line, the DB the second.
- **State change + event + audit in one transaction** (REL-010, NOTIF-001):
  ```ts
  await prisma.$transaction(async (tx) => {
    await tx.booking.update({ ... });                                  // your own table only
    await outbox.append(tx, { eventType: 'booking.accepted', schemaVersion: 1,
      aggregateType: 'booking', aggregateId: id, payload: { bookingId: id } });
    await audit.write({ actor, action: 'BOOKING_ACCEPTED', object: { type: 'booking', id },
      before, after, reason, source: { ip: req.ip, client: 'partner-app' } }, tx);
  });
  ```
  Payloads: IDs and states only. Admin actions must pass `reason`.
- **Consume events** (A10 notifications, analytics later): in your module `onModuleInit`, `registry.register({ name: 'notifications', eventTypes: ['booking.accepted'], handle })`, and import your module in `WorkerModule`. **Delivery is at-least-once**: dedupe on `message.id` (e.g. a processed-event row with the event ID as unique key, written in the same transaction as your side effect), and make `handle` idempotent. Throwing = retry with backoff; after `OUTBOX_MAX_ATTEMPTS` the job is copied to `outbox.dead-letter`.
- **Mask your own append-only text**: A04 (`job_event.reason/source_metadata`) and A09 (`refund.reason`, ledger `reason`) must run `maskReason()` / `maskPii()` / `maskSource()` from `@kaamkaro/platform` before insert (SEC-REVIEW-T2.3 #10, second bullet).
- **Logging**: inject `APP_LOGGER` (`Logger`) or use `createLogger`. Never log raw request bodies; the masker is a safety net, not a licence.
- **Tests without DB**: use `InMemoryIdempotencyStore` and override `IDEMPOTENCY_STORE` / `IDEMPOTENCY_SCOPE_RESOLVER` (see `src/platform/platform.e2e-spec.ts`).
