## Security fix round (2026-10-23, after SEC-REVIEW CHANGES-REQUIRED + QA PASS)
Sources: docs/security/SEC-REVIEW-T2.1.md, docs/security/dependency-exceptions.md, docs/qa/T2.1-qa.md.
- **#1 (S2) Sentry PII — fixed.** `packages/platform/src/sentry.ts`: `sendDefaultPii` removed (SDK 11 ignores it). An explicit deny-all `SENTRY_DATA_COLLECTION` switches off `userInfo`, `cookies`, request/response headers, bodies (`httpBodies: []`), `urlQueryParams`, GraphQL, genAI, `databaseQueryData`, `queues` and `stackFrameVariables`. `scrubSentryEvent` runs in both `beforeSend` and `beforeSendTransaction`. It keeps only the request method, the URL without its query, the `user-agent` header and `user.id`, and it strips queries from breadcrumb URLs. The options are typed `satisfies NodeOptions`; platform gained a type-only peer dependency on `@sentry/nestjs`. `services/api/src/instrument.ts` passes only these options.
  - Unit tests: `packages/platform/src/sentry.spec.ts`.
  - Fake-transport test: `services/api/src/sentry-privacy.e2e-spec.ts`. It runs the real Nest app with Sentry and an in-memory transport. A POST with a JSON body (phone + OTP), `Authorization`, `Cookie`, `X-Forwarded-For` and a query string throws. The error event is delivered and contains none of these values, and has no `ip_address`, `cookies`, `query_string` or `authorization` keys.
  - Control run (temporary file, deleted): the same test with the SDK's default options FAILED because the phone number leaked. So the test does catch leaks.
  - The test generates its secret values at runtime, because Sentry's stack-frame source context would otherwise contain them.
- **#2 (S3) Audit gate — fixed.** The CI gate is now `pnpm audit --audit-level high` (no `--ignore-unfixable`, no `|| true`). The only waivers are `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml`, commented as EX-001 / EX-002 and pointing to `docs/security/dependency-exceptions.md`. pnpm wrote that block during my earlier local `--ignore-unfixable` run and I did not notice, so the earlier handoff claim that CI kept the two advisories visible was wrong. The old "report all" step is replaced by an informational step that never fails. It prints the exception IDs and the `pnpm why node-forge braces` dependency paths.
- **#5 — fixed.** Every action is pinned to a full commit SHA with a version comment:
  - `actions/checkout` 3d3c42e5… v7.0.1
  - `pnpm/action-setup` ea17c68d… v6.1.0
  - `actions/setup-node` 949feb24… v7.1.0
  - `actions/setup-java` b843ebf9… v6.1.0

  Every checkout has `persist-credentials: false`. `.github/dependabot.yml` updates github-actions weekly.
- **#4 — fixed.** `"allowBackup": false` is set in `apps/customer/app.json` and `apps/partner/app.json`. This is a small A00-approved change in the A11/A12 lanes; **A11/A12: keep it**. The guard (`checkExpoConfig`) requires `allowBackup === false`, and main/merged release manifests must have `android:allowBackup="false"`. The regenerated prebuild manifests show `allowBackup="false"`.
- **#8 — fixed.** Manifest attributes are parsed with double or single quotes. A `<uses-permission>` without a parseable `android:name` (missing, empty or unquoted) fails closed. Tests added.
- **#13 — fixed.** `.gitignore` now ignores `*.env`, `.envrc` and `*.secret*`; `.env.example` is still tracked. Hygiene test updated.
- **QA F-03 — fixed (boot fails).** `SENTRY_DSN` is in `REQUIRED_WHEN_DEPLOYED`, so staging/production refuse to boot with an empty DSN (INFRA-005 acceptance "Sentry + alerts configured"; BP §34, §31.2; D-001).
